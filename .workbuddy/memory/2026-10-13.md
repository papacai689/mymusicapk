## 23:17 播放页暂停"不好用/卡" — 根因与修复（提交 76966c5）
- **根因1（点了没反应）**：播放页点暂停 → `requestToggle()` 写 store 计数 → 迷你播放器 effect 里用 `!sharedPlayer.playing` 判方向 → 原生状态每 500ms 才回传，曲目刚装载/页面重新挂载时它为 false → 「暂停」被算成「播放」，于是点了没反应，要多点几次。来回切页面尤其容易撞上。
- **根因2（卡）**：PlayerScreen 用 `usePlayerStore()` 订阅整个 store，进度每 500ms 写一次 store → 整个页面（歌词几十个 Text、队列）跟着重渲染，按钮要等这一轮渲染完才响应。
- **修法**：
  - 新增 `services/player.js::togglePlayback()` 作为唯一落点，方向规则 = `!(store.isPlaying || sharedPlayer.playing)`（任一方在播就暂停），同步执行并立刻回写 store。
  - PlayerScreen / MiniPlayer 都直接调它；`requestToggle`/`toggleRequested` 已从 playerStore 删除。
  - PlayerScreen 改为逐字段订阅 + `useMemo` 缓存唱片与歌词列表。
  - 边界：`loadedKey` 为空（刚恢复的会话未装载）时播放页的播放键走 `load(current)` 而不是 toggle。
