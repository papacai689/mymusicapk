## 移动网络速度分析（21:28，WiFi 快、用户问移动网络）
本机无法直连手机蜂窝网，改用「请求次数 + 数据包大小 + 稳定性」三个移动网络命门指标实测：
- **流量**：整改后首屏 ~122KB（4 次 oiapi 搜索 27.8KB + 18 张 120px 封面 94.6KB），整改前 ~114KB。流量几乎持平——**不是流量问题**。
- **往返次数(RTT)才是关键**：整改后封面是直链（1 RTT）；整改前要先问 GD types=pic 拿地址再下图（2 RTT）。移动网络 RTT 高（50~150ms），18 张图省 18 个 RTT，累计差好几秒。
- **稳定性差距悬殊**（10 次抽样）：oiapi 10/10 成功（0.2~0.7s）；GD 仅 4/10 成功，6 次 8s 超时。移动网络抖动下 GD 超时会触发等待，体验雪上加霜。
- 单次数据：oiapi 搜索 30 首 gzip 后仅 7.1KB；封面 120px 5.4KB / 250px 19.6KB / 500px 59.2KB；meting 190B。
- 结论：整改方向正确——移动网络的收益来自「少 RTT + 不超时」，不是省流量。WiFi 下 RTT 低所以差异被掩盖，蜂窝网高延迟下差距会明显放大。

## 循环模式修复（22:06）— 关键坑
用户反馈「播放页循环那个还没动」。真因：**上次改的 `repeat-one` 图标名在当前 @expo/vector-icons 版本里根本不存在**！实测 glyphMap 只有 `repeat`/`repeat-outline`/`repeat-sharp`/`shuffle`，没有 `repeat-one`。Metro 日志刷屏 `WARN "repeat-one" is not a valid icon name`，单曲循环图标渲染失败 → 看起来像没切换。
- 修复：`PlayerScreen.js` 单曲循环图标改为有效的 `repeat`（实心）并加红色数字「1」角标（`modeOneBadge`，绝对定位在图标右上）；列表循环 `repeat-outline` 灰、随机 `shuffle` 红。
- 同时把循环按钮从「点一下循环切换(cycleMode)」改成「点一下弹三选一菜单」：新增 `showMode` state + `MODE_OPTIONS`（列表/单曲/随机，各带图标+说明）+ `pickMode` + Modal（复用 quality 弹窗样式）。删掉 `cycleMode`。
- **教训**：改 Ionicons 图标名前必须查 `node_modules/@expo/vector-icons/build/vendor/react-native-vector-icons/glyphmaps/Ionicons.json`，不要凭印象写 `repeat-one` 这类名字，无效名只在运行时 WARN、语法检查发现不了。
- 验证：语法 OK；无 repeat-one 残留；所有图标名校验有效；cycleMode 已清除。
- **后续用户改主意（22:08）**：不要弹窗，改回点击直接切换。已移除 showMode/MODE_OPTIONS/pickMode/模式 Modal，恢复 `cycleMode`，保留有效图标 + 单曲「1」角标 + 红色高亮。
- **真·根因（22:17）**：用户仍反馈"没任何反应"。真正的 bug 不是图标也不是热更新——`playerStore.setMode` 只接受**具体值**（`setMode: (mode) => set({mode: PLAY_MODES.includes(mode) ? mode : '列表循环'})`），而 `cycleMode` 传的是函数式 updater `(value) => ...`，`PLAY_MODES.includes(函数)` 恒为 false → 每次都被兜底成「列表循环」，点任意次都不变。这才是用户最初说"只有列表循环"的根因，之前几轮只改图标/弹窗都没碰到它。
  - 修复：`cycleMode` 用组件里的 `mode` 算出下一个字符串再 `setMode(order[(index+1)%3])`。Node 验证轮转正确：列表→单曲→随机→列表。全项目仅此一处调用 setMode。
  - **教训**：zustand 的 action 如果自己写了 `set({...})` 而不是转发给 `setState`，就**不支持函数式 updater**，调用时必须先算值。改 action 调用前先看它的定义。

- `playerStore.subscribe` 里距上次写盘 ≥4s 时**同步** `JSON.stringify` 整条队列（上百首完整歌曲对象）+ `setItem`，正好卡在 setQueue→navigate 那一帧。改为 `scheduleWrite` 走 `setTimeout(0)`，写盘不阻塞同步栈。

- 验证：语法 OK；单测 7/7；无 JS 运行时错误；服务 HTTP 200。待用户真机确认卡顿是否消除。
- 备注：日志里的 `Failed to start the expo-audio playback service / service binding failed` 是 Expo Go 无后台播放权限所致（需 development build），非本项目代码 bug，不影响前台播放。
